# Privacy control composition acceptance

Scope: remaining Stage 7 privacy-control verification, using the actual application composition, temporary SQLite profile, fixed injected time, fake activity source and offscreen Qt. This is test coverage, not another feature stage. Existing component tests cover memory deletion/future context, conversation deletion/voice cancellation and explicit microphone cancellation. Add application-level checks for activity opt-in/pause and disabling reminders while a reply proposal is open.

Design: run each scenario in its own subprocess with temporary LOCALAPPDATA. Inject a fixed UTC+8 resolver through SystemClock, fake activity source, unavailable voice factories and credential-access guards before application construction. Seed only a public task via TaskService. Use the real settings-dialog signals, scheduler and SQLite services. Check no activity polling before opt-in or after pause, persistence visible to a fresh service, reminder disablement dismissing the current card/reply without applying its pending action, and no polling after reminder disablement. Stop the scheduler and quit the owned application. Never access real microphone, startup registry, credentials, private profile or network.

Plan: implement the two composition scenarios; execute focused lifecycle tests; inspect any failures before changing production code; run full regression; independent review; commit and normally integrate under the user's renewed explicit merge authorization. No manual Windows behavior, packaged launch or voice naturalness acceptance is implied.

Root cause discovered by acceptance: pausing activity passes, but disabling reminders still samples activity. ProactiveReminderService eagerly loads task/goal/reminder state and calls the activity source before the pure domain engine returns REMINDERS_DISABLED. A second unit reproduction shows two disabled evaluations still query tasks twice. This is unnecessary collection while the consumer is disabled.

Bounded design correction before implementation: after reading preferences and the injected clock snapshot, return the existing SILENT/REMINDERS_DISABLED decision immediately when disabled. No task, goal, reminder-state or activity reads; no writes. Keep domain engine's existing disabled guard for direct pure callers. On every later tick re-read preferences, so re-enabling resumes fresh evaluation. Do not disable the separate activity preference, alter quiet-hours policy or change explicit task responses. Retain current preference/time-read failure behavior. RED evidence: composition test reports “Disabled reminders still sampled activity”; unit test reports two task reads while disabled. This small application-boundary guard preserves the existing domain policy and avoids a new abstraction/dependency.

After the guard, all 38 focused application/activity/lifecycle tests passed. Real-Windows full regression: 801 passed in 13.58 seconds; compileall, pip check and diff whitespace checks passed. Both new composition scenarios run real Qt signals, services and temporary SQLite, with fake time/devices only. Manual user experience and packaged/runtime gates remain separate. Fresh-context independent review found no actionable issues and independently ran 30 targeted tests successfully. Changed/new files passed a secret-pattern inspection; no private evidence or runtime/model files are included.
